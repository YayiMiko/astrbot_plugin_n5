本次请求是“漫画抽卡”：用户会提供出场角色，也可能在角色之后指定一个简短剧情。规划器必须创作一页可视化、连贯且适合 NovelAI V5 的微型剧情，不能把角色列表原样扩写成无事件的合照。

1. 默认生成竖向四格漫画，并在主 `prompt` 中逐字使用 `Panel 1`、`Panel 2`、`Panel 3`、`Panel 4` 描述全部四格。只有用户明确要求更少格数时才允许 1 至 3 格；没有明确要求时不得自行缩减。
2. `[COMIC_DRAW_PLOT_SEED]` 中如果是 `AI_INVENT_STORY`，剧情采用“建立情境 → 发展或升级 → 转折 → 收束或笑点”的四拍结构，主题、地点、道具和事件由规划器自由选择。如果其中是用户文字，该文字就是不可替换的剧情种子：必须把它扩写成贯穿四格的主要动作与因果链，不能改成别的剧情，不能只在一格角落出现，也不能弱化成背景物件。两种情况都必须适合用户给出的全部角色，不改变身份，不新增具名角色，也不把服装或作品引用误当成出场人物。
3. 优先用动作、表情、视线、构图变化和可见结果讲故事。对白不是必需；只有对白能明显改善笑点或叙事时才加入，每个气泡应简短，并同时写引号原文与 `Text: 原文`。
4. 主 `prompt` 需要完整描述页面比例、清楚的分格边框、统一媒介与色彩、四格阅读顺序、每格景别、角色空间位置、场景连续性和事件结果。使用 `comic, 4koma` 等稳定锚点，并充分利用 V5 自然语言，不受旧 Tag 数量或短 Prompt 模板限制。
5. 每个人物槽位的 `character_prompts` 必须保持本页服装、道具和身份呈现一致，并至少用一个 `Panel 数字` 明确其出现格、动作、表情、视线或互动。角色可以出现在多格，不得加入 `solo`，不得因重复出场创建新身份。
6. 相邻格必须发生可见状态变化：人物位置、动作、表情、共同争夺或操作的物件、环境结果中至少一项发生推进。Panel 1 建立起因，Panel 2 和 Panel 3 展示连续动作或升级，Panel 4 显示明确结果；禁止只画同一坐姿、同一场景的表情差分。
7. 在合规范围内保持抽卡的新鲜感，主动变化喜剧、日常、奇遇、动作、温情或反转主题；不要总是生成站立合照、白背景角色卡或没有因果关系的四张插画。
8. 最终只返回既有单行 JSON 协议，不输出剧情摘要、解释、Markdown 或额外字段。
