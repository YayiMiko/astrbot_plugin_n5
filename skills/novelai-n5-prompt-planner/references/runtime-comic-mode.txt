本次请求使用 NovelAI V5 漫画模式。用户明确要求的漫画页优先于通用模式中“单一连续画面”“solo”“不要多个时间点”的默认规则。

插件会在用户请求后附加 `[COMIC_STORYBOARD_BEGIN]` 至 `[COMIC_STORYBOARD_END]`，其中是已验证的镜头级分镜。它是本次页面的权威结构：必须逐格保留其景别、机位、人物站位、动作、状态变化、连续性和对白，再把这些视觉决定翻译成适合 NovelAI V5 的英文自然语言与必要标签。不得自行合并、改序、删格或替换剧情。

1. 主 `prompt` 必须包含适合题材的 `comic`、`manga`、`4koma`、`2koma` 或等价视觉锚点，并用具体英文自然语言描述页面方向、分格数量、分格大小、阅读顺序以及每格的镜头和事件。用户没有指定格数时，根据剧情选择最少且足够的 2 至 4 格。每个 `Panel N` 在主 Prompt 中只出现一次；把该格的位置、相对尺寸、景别和事件合并在同一个 Panel 段落中，不要先列一次版式再重复一次内容。
2. 把整页共享的媒介、线条、色彩、背景连续性和分格边框写入主 `prompt`。按 Panel 1、Panel 2 的顺序明确每格内容，不能只写抽象剧情梗概；也不要复述 beat、state_change 等规划字段，同一个可见事实只写一次。
3. 同一角色可以在多个分格重复出现；不得加入 `solo`，也不得把 `multiple views`、`duplicate`、`panels` 或 `comic` 当作负面概念。基础人数表示故事中的不同身份数量，不把同一角色跨格重复出场误算成新增身份。
4. 每个人物槽位仍只对应一个身份。该人物的 `character_prompts` 值必须先写本页稳定服装和道具，再按分格描述其动作、表情、视线和对白，使跨格身份一致。不要为同一身份创建新槽位。
5. 多人物互动继续使用 source#、target#、mutual# 标签作为辅助，但分格归属、左右位置、前后关系和动作结果必须同时用自然语言说清楚。引用人物槽位时按其顺序使用 `the first character`、`the second character` 等稳定称呼，不要退化为多个含混的 `person`；分镜要求共同入镜时，不能为了特写裁掉另一名核心角色。
6. 只有用户明确要求可见文字时才加入对白，并把它保持短小、绑定到说话者和分格；每段需要绘制的原文同时保留在引号和 `Text: 原文` 中。用户没有明确要求文字时，主 Prompt 与人物 Prompt 都不得出现 `Text:`、引号对白、标题、旁白、字幕或气泡，使用 `no text` 并完全依靠画面叙事。
7. 不设置固定 Tag 数量、句数或旧长度目标。复杂漫画可以充分使用 V5 的长 Prompt，但每个细节必须属于明确分格，避免同一格出现互斥动作、镜头或时间。
8. 只返回既有 JSON 协议；不要输出分镜解释、Markdown、代码块或额外字段。
